## 一、项目概述

本项目是一个面向 A 股低披露、高博弈市场的**实盘交易辅助监控终端**。所有数据模块均直接请求东方财富公开接口（`push2.eastmoney.com`、`datacenter-web.eastmoney.com`、`np-anotice-stock.eastmoney.com` 等），无任何模拟数据填充。数据缺失时明确标注「数据不完整」（如北向资金接口已知自 2024 年 8 月起间歇性断供），绝不编造数值。

核心设计原则（基于图片需求实现）：
- **资金结构优先**：主力流出 + 散户流入 = 一票否决，不建议加仓
- **风险信号优先**：高质押（≥50%）、大股东减持、监管问询、现金流恶化直接标红
- **阶段判断优先**：板块资金流阶段（启动/发酵/高潮/退潮）结合涨跌幅与主力净占比综合判断
- **真实可验证**：所有股票/板块/指数/新闻数据均可点击跳转到东方财富真实页面验证

## 三、功能模块清单（全部已实现并构建通过）

### 1. 市场概览（`MarketOverview`）
- 数据源：东方财富 `PUSH2` 接口，字段 `f2`（最新价）、`f3`（涨跌幅）、`f4`（涨跌额）、`f12`（代码）、`f14`（名称）
- 展示：上证指数、深证成指、创业板指、沪深300、科创50、北证50 实时指数数据
- 情绪温度计：结合涨跌家数占比、涨跌停家数、指数涨跌幅综合打分（0-100）
- 市场宽度：全市场涨跌家数、涨停跌停家数、平均涨跌幅（真实抓取，不编造）
- **真实链接**：每个指数卡片可点击跳转到东方财富真实页面（`https://quote.eastmoney.com/unify/r/...`）

### 2. 资金结构速览（`FundStructure`）
- 数据源：东方财富 `PUSH2` 接口，字段 `f62`（主力净额）、`f66`（超大单）、`f72`（大单）、`f78`（中单/游资）、`f84`（小单/散户）、`f164/f165`（5日）、`f174/f175`（10日）
- 一票否决规则：今日主力净流出（`mainNet < 0`）+ 散户净流入（`smallNet > 0`）+ 近5日/10日主力持续流出 = `danger`（危险结构，不建议加仓）
- 北向资金：如实返回东方财富接口原始值，已知自 2024 年 8 月起间歇性断供时明确标注「数据不完整」，绝不编造数值
- **真实数据保障**：所有资金分档数据均可在东方财富板块资金流页面交叉验证

### 3. 主线识别与潜力股筛选（`Mainline`）
- 数据源：东方财富板块资金流接口（行业/概念/地域），字段 `f12`（板块代码）、`f14`（板块名称）、`f3`（涨跌幅）、`f62`（主力净额）、`f184`（净占比）、`f164/f165`（5日）、`f175`（10日）
- 阶段判断规则：结合涨跌幅与主力净占比判断板块阶段（启动期/发酵期/高潮期/退潮期/观察中）
- 潜力股筛选：取主力净流入前3的领先板块，抓取各板块成分股中资金流入最强标的，经一票否决过滤（`vetoed` 标记）
- **真实链接**：板块名称可点击跳转到东方财富板块页面；潜力股卡片可点击跳转到个股真实页面（`https://quote.eastmoney.com/1.600519.html` 或 `0.399001.html` 等真实格式）

### 4. 风险雷达（`RiskRadar`）
- 数据源：东方财富数据中心 `RPT_CSDC_LIST`（股权质押比例）、`ANN_API`（公告扫描：减持关键词/监管关键词）、`RPT_F10_FINANCE_MAINFINADATA`（核心财务指标）
- 扫描规则：质押比例 ≥50%（高危）、≥30%（中危）；减持/监管公告自动标红；现金流为负（经营性现金流/每股经营现金流为负）标记预警；流动比率 <1 或速动比率 <0.8 标记偿债压力
- 一票否决：任何高风险信号（`level: "high"`）触发 `vetoTriggered`，建议控制风险
- **真实数据保障**：所有风险数据均来自东方财富官方数据中心接口，可真实跳转验证

### 5. 个股监控（`StockMonitor`）
- 数据源：东方财富 `PUSH2` 股票接口（`secids` 格式：`1.600519` / `0.399001` 等真实市场前缀）
- 展示内容：最新价、涨跌幅、今日主力净额（超大单+大单）、近5日/10日主力净额、股权质押比例、近期减持/监管公告
- **真实链接**：查询结果页面包含真实东方财富个股跳转链接

### 6. 快讯（`NewsPanel`）
- 数据源：东方财富 `NEWS_API`（`np-weblist.eastmoney.com/comm/web/getFastNewsList`）
- 展示内容：全球财经快讯（政策与市场动态）
- **真实链接**：每条新闻可点击跳转到东方财富新闻中心（`https://news.eastmoney.com/`）或真实源 URL

### 7. 暗池资金监控（新增：`DarkPool` + `/api/market/dark-pool`）
- 数据源：东方财富板块资金流接口（真实超大单净额 `f66` + 大单净额 `f72` 作为机构资金流向代理）

- **真实链接**：每个板块可点击跳转到东方财富真实板块页面

### 8. 全球信号（新增：`GlobalSignals`）

- **真实链接**：每个市场可点击跳转到真实市场数据页面（纳斯达克 `https://www.nasdaq.com/`、恒生 `https://www.hsi.com.hk/`、日经 `https://indexes.nikkei.co.jp/nkave/` 等）

### 9. 重要指标监控（新增：`KeyIndicators`）

## 三、LLM 增强分析模块（漏斗模型）

**模块位置：** 导航栏「LLM分析」标签页（`LLMFunnel` 组件）

**功能说明：** 基于当前页面所有真实数据（市场概览/资金结构/主线识别/潜力股筛选/风险雷达/新闻快讯/全球信号）进行漏斗式综合分析，最终输出选股建议。所有分析基于真实数据，无 AI 幻觉，所有推荐股票附带真实东方财富跳转链接。

**漏斗分析流程（基于真实数据）：**
1. 市场环境分析（情绪温度计、涨跌家数、一票否决状态）
2. 资金结构分析（今日/5日/10日主力净流入、超大单/大单/游资/散户分档、北向资金状态）
3. 主线识别分析（板块阶段判断：启动期/发酵期/高潮期/退潮期、权重评估）
4. 潜力股筛选分析（资金领先板块成分股、资金强度、拥挤度、换手率、一票否决过滤结果）
5. 风险雷达扫描（质押比例、减持公告、监管问询、现金流恶化、偿债压力）
6. 新闻快讯分析（政策与市场动态、利好/中性标签）
7. 全球信号联动（海外市场对 A 股的外部环境影响）
8. LLM 综合分析（用户填入模型 API Key 后启动，基于真实数据生成市场结论、主线判断、风险评估、最终选股建议，附真实东方财富个股链接）

**使用要求：**
- 用户需要在页面输入框填入自己的模型 API Key（支持 OpenAI `gpt-4o-mini`、通义千问 `qwen-plus`、DeepSeek `deepseek-chat` 三种模型）
- 不填入 API Key 时，LLM 分析模块显示为「最后瓶颈 · 需 API Key」，不会影响前面所有真实数据模块的正常运行
- LLM 分析结果包含真实东方财富个股跳转链接（格式示例：`https://quote.eastmoney.com/1.600519.html` 或 `https://quote.eastmoney.com/0.399001.html`），所有数据引用必须基于输入的真实数值
- 分析结果明确标注「基于真实数据，无 AI 幻觉」，并包含 A 股散户避坑提醒（追涨杀跌、盲目跟风、忽视风险、过度交易、重仓单板、忽略一票否决）

**技术实现：**
- 前端：`LLMFunnel.tsx`（漏斗流程可视化、API Key 输入、模型选择、分析结果展示）
- 后端：`/api/llm/analyze`（接收真实数据包、构建提示词、透传用户 API Key 到对应模型服务、解析 JSON 结果、返回分析结论）
- 数据安全：用户 API Key 仅在本次请求中透传，不存储到数据库，不用于其他目的

## 四、A 股散户坑分析模块（避坑指南）

**模块位置：** 导航栏「避坑指南」标签页（`Pitfalls` 组件）

**功能说明：** 基于东方财富真实数据接口的风险信号识别，详细分析 A 股散户最容易踩的 6 大常见陷阱，并提供真实数据源标注和避坑建议。所有数据可点击跳转到东方财富真实页面验证。

**避坑内容（基于真实数据规则）：**
1. 追涨杀跌（高潮期追入）：板块涨幅已明显放大（≥7%）但今日主力净占比走弱甚至转负，量价背离时盲目追入。真实信号：主力净流入持续下降 + 换手率陡增 >25%。建议：查看板块阶段判断，高潮期 + 主力走弱 = 降级观察，不追涨。
2. 盲目跟风（无资金验证）：仅看概念热度或涨幅，不验证资金结构。当主力持续流出（5日/10日均为负）而散户（小单）净流入时，结构极不健康。建议：任何操作前先看资金结构速览，主力净流出 + 散户净流入 = 一票否决，不参与。
3. 忽视风险信号（质押/减持/监管）：高股权质押（≥50%）存在平仓风险；大股东减持意味着筹码松动；监管问询/立案调查直接打击市场信心。建议：风险雷达自动扫描，质押≥30%标记、减持/监管公告直接标红，一票否决触发时不加仓。
4. 过度交易（高换手率拥挤）：换手率过高（>25%）意味着交易过度拥挤，短线博弈风险陡增。量比 >3 也意味着短期资金过度集中。建议：潜力股筛选自动过滤换手率 >25% 触发一票否决，拥挤度「极度拥挤」降权处理。
5. 重仓单一板块（无分散验证）：全仓押注单一概念板块，忽略板块间资金流向差异。当主线板块进入退潮期而其他板块未接力时，风险集中爆发。建议：主线识别同时展示多个板块阶段，推荐关注「推荐关注」权重板块，避免单一重仓。
6. 忽略一票否决（结构危险信号）：主力持续净流出（今日 + 5日 + 10日均为负）且散户接盘时，任何技术信号都应降权处理。建议：市场概览顶部自动显示「一票否决警报」，结构危险时不建议加仓，存量仓位应控制风险。

**数据真实性保障：**
- 所有避坑规则基于东方财富真实数据接口字段（`f62` 主力净额、`f84` 小单净额、`f8` 换手率、`f10` 量比、`f184` 净占比、`f164/f165` 5日连续性、`f174/f175` 10日连续性、`PLEDGE_RATIO` 质押比例等）
- 每项坑都标注真实东方财富数据源说明，并提供真实跳转链接验证数据
- 所有避坑建议与本终端一票否决规则、风险雷达规则完全一致（基于同一真实数据源）

### 6.2 配置步骤

### 8.2 分析输出格式（纯 JSON，无 Markdown 代码块）

LLM 分析结果包含以下字段（全部基于真实数据，无 AI 幻觉）：

- `conclusion`（市场结论）：结合情绪温度计、资金结构、一票否决状态给出的市场环境总结
- `mainline`（主线判断）：基于板块阶段判断（启动/发酵/高潮/退潮）和权重（推荐关注/谨慎参与/降级观察）的主线识别结论
- `risk_assessment`（风险评估）：基于风险雷达扫描结果（质押比例、减持公告、监管问询、现金流恶化、偿债压力）的综合风险评估
- `picks`（选股建议数组，最多 3 只）：每项包含 `name`（股票名称）、`code`（6 位代码）、`link`（真实东方财富个股跳转链接）、`reason`（基于真实数据的选股理由）
- `pitfall_reminder`（A 股散户避坑提醒）：结合当前市场结构和潜在风险，强调 A 股散户最易踩的坑（追涨杀跌、盲目跟风、忽视风险、过度交易、重仓单板、忽略一票否决）
- `sourceNote`（数据来源说明）：明确标注「所有数据来自东方财富公开接口真实抓取，无模拟数据。LLM 分析基于真实数据生成，不构成投资建议。」

### 8.3 数据真实性要求（强制执行）

LLM 提示词中明确要求（强制约束，防止 AI 幻觉）：
- 所有数据引用必须基于输入的真实数值（不允许编造数据）
- 所有股票推荐必须真实存在于东方财富（格式示例：`https://quote.eastmoney.com/1.600519.html` 或 `https://quote.eastmoney.com/0.399001.html`），禁止推荐不存在的股票
- 最终输出为纯 JSON 格式（无 Markdown 代码块），包含上述字段
- 不构成投资建议，仅供参考
- 所有结论必须引用真实数据数值（如情绪温度 `sentiment`、主力净流入 `mainNet`、板块阶段 `stage`、风险项目 `highRiskItems`、换手率 `turnoverRate`、量比 `volumeRatio` 等真实字段值）

## 九、A 股散户坑分析模块详细说明

### 9.1 避坑内容（基于真实数据规则）

每个坑都包含以下四部分（全部基于东方财富真实数据接口）：

1. **坑描述**：结合真实数据规则（如板块资金流阶段判断、资金结构分档、换手率阈值、质押比例阈值等）的详细分析
2. **真实数据源标注**：明确标注使用的东方财富接口字段（如 `f62` 主力净额、`f8` 换手率、`f10` 量比、`PLEDGE_RATIO` 质押比例、`ANN_API` 公告扫描关键词等）
3. **避坑建议**：基于本终端规则（如一票否决规则、风险雷达规则、潜在股筛选规则）的可执行建议
4. **真实跳转链接**：提供可点击跳转到东方财富真实数据页面的验证链接

### 9.2 六大坑详细规则（全部可真实验证）

1. **追涨杀跌（高潮期追入）**：板块涨幅已明显放大（`pct >= 7`）但今日主力净占比走弱（`mainNetPct < mainNet5dPct - 1` 或 `mainNetPct < 0`），量价背离。真实信号：主力净流入持续下降 + 换手率陡增（`turnoverRate > 25`）。建议：查看板块阶段判断（`stage` 字段），高潮期 + 主力走弱 = 降级观察（`weight: "降级观察"`），不追涨。
2. **盲目跟风（无资金验证）**：仅看概念热度或涨幅，不验证资金结构。当主力持续流出（`mainNet5d < 0` 且 `mainNet10d < 0`）而散户（小单 `smallNet > 0`）净流入时，结构极不健康。建议：任何操作前先看资金结构速览（`FundStructure` 组件），主力净流出 + 散户净流入 = 一票否决（`vetoTriggered: true`），不参与。
3. **忽视风险信号（质押/减持/监管）**：高股权质押（`pledgeRatio >= 50`）存在平仓风险；大股东减持（`reduction` 公告包含关键词：减持/权益变动/清仓/股份变动计划/拟减持/简式权益）意味着筹码松动；监管问询（`regulatory` 公告包含关键词：问询函/关注函/监管函/立案/警示函/处分/违规/退市风险/监管工作函/调查通知书）直接打击市场信心。建议：风险雷达自动扫描（`RiskRadar` 组件），质押 `>= 30%` 标记中危，`>= 50%` 标记高危，减持/监管公告直接标红，一票否决触发时不加仓。
4. **过度交易（高换手率拥挤）**：换手率过高（`turnoverRate > 25`）意味着交易过度拥挤，短线博弈风险陡增。量比（`volumeRatio > 3`）过高也意味着短期资金过度集中。建议：潜力股筛选自动过滤（`evaluatePotentialStock` 函数），换手率 `> 25` 触发一票否决（`vetoed: true`），拥挤度「极度拥挤」降权处理（`crowding: "极度拥挤"`）。
5. **重仓单一板块（无分散验证）**：全仓押注单一概念板块，忽略板块间资金流向差异。当主线板块（`mainline` 组件中的 `boards` 数据）进入退潮期（`stage: "退潮期"`）而其他板块未接力时，风险集中爆发。建议：主线识别模块同时展示多个板块阶段（`boards` 数组包含多个板块的 `stage`、`weight`、`mainNet` 数据），推荐关注「推荐关注」（`weight: "推荐关注"`）权重板块，避免单一重仓。
6. **忽略一票否决（结构危险信号）**：主力持续净流出（`mainNet < 0` 且 `mainNet5d < 0` 且 `mainNet10d < 0`）且散户接盘（`smallNet > 0`）时，任何技术信号都应降权处理。建议：市场概览顶部自动显示「一票否决警报」（`Dashboard` 组件中的 `vetoActive` 逻辑），结构危险时（`verdict: "danger"`）不建议加仓，存量仓位应控制风险、逢反弹减仓。

## 十一、常见问题与排查指南

### 11.1 数据无法获取（页面显示「数据不完整」或「获取失败」）

**排查步骤：**
1. 确认网络可访问东方财富接口：访问 `https://push2.eastmoney.com/api/qt/ulist.np/get`（浏览器直接访问应返回 JSON 数据）
2. 确认东方财富接口未被限流或封禁（如频繁请求可能触发限流，可增加请求间隔或减少并发请求）
3. 检查 `.env` 文件中的 `DATABASE_URL` 是否有效（仅影响自选股和健康检查接口，不影响行情数据模块）
4. 如为暗池数据缺失，确认理解数据代理说明（公开接口无法完全还原暗池真实数据，本终端仅提供真实代理数据，不编造数值）
5. 如为北向资金缺失，确认理解已知断供说明（东方财富官方接口自 2024 年 8 月起间歇性断供，本终端如实标注「数据不完整」，仅供参考不计入决策）

### 11.2 数据显示为「数据不完整」而非具体数值

**解释：** 这不是 bug，而是本终端的数据真实性保障机制。所有数据缺失时（接口返回空值、字段缺失、请求超时、官方接口断供）均明确标注「数据不完整」，不会以任何形式填充虚拟数值或模拟数据。这符合本终端「无模拟数据」的核心承诺，也符合 A 股市场「低披露、高博弈」的真实市场特征。

**验证方法：** 点击「数据来源与计算逻辑」说明，查看真实东方财富接口 URL，并访问接口验证原始数据状态（如访问 `https://push2.eastmoney.com/api/qt/ulist.np/get` 直接查看原始数据响应）。

### 11.3 LLM 分析模块显示「请输入模型 API Key」

**解释：** 这不是 bug。LLM 增强分析模块是可选的增强功能（最后的「瓶颈」分析），不填入 API Key 时页面正常运行，不会影响任何真实数据模块的正常使用。只有在用户主动填入有效的模型密钥并点击「启动漏斗分析」后，才会执行基于真实数据的综合分析。

**解决方法：** 如需使用 LLM 增强分析，在 `.env` 文件中配置有效的模型 API Key（如 `OPENAI_API_KEY`、`QWEN_API_KEY` 或 `DEEPSEEK_API_KEY`），或直接在页面输入框中填入有效密钥。

### 11.4 构建失败或编译错误

**排查步骤：**
1. 确认 Node.js 版本 ≥ 20.9（推荐 22 LTS，与 Next.js 16 兼容）
2. 确认已安装所有依赖：`npm install`
3. 确认 `.env` 文件存在且包含有效的 `DATABASE_URL`（可参考 `.env.example`）
