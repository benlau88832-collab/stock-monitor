# stock-monitor 项目审查报告
## 定位核查：「波段操作 + AI 投研大脑」目标 vs 代码现状

- 审查对象：`github.com/benlau88832-collab/stock-monitor`，分支 `arena/019fb619-stock-monitor`
- 审查方式：全量静态代码通读（`server/` 约 60 个模块 + `src/` 约 150 个组件/lib + 项目历史审查文档 6 份）
- 审查目标：验证「持股周期 7 天～数月的波段操作」+「挖掘产业链、AI 贯穿全局的投研大脑」这两个核心诉求，在当前代码里究竟落地了多少
- 结论先行：**你的直觉是对的，而且比你想的更严重**。这不是"优化不到位"，而是**系统的骨架从一开始就是为另一个目标（游资打板/涨停接力的日内-隔夜操作）搭建的**，"波段""产业链""AI 投研大脑"更多是后期贴上去的标签、组件名和只言片语的 prompt 措辞，底层的数据模型、决策引擎、AI 使用方式都没有真正转向。

| 信息聚合有深度 | 数据源仅覆盖：东方财富行情/公告/资金/龙虎榜、财联社快讯、百川大宗商品页面爬取；**没有研报、没有机构调研纪要、没有股东户数/大宗交易折溢价的系统化利用、没有宏观日历、没有产业数据（如中国汽车工业协会销量、光伏协会排产等）**，"行业博弈"调研阶段本质是搜索引擎调用，深度约等于你自己搜一下 | 🟠 广度和深度都不够 |

一句话总结：**这套系统目前是一台"游资打板信息终端"，穿了一件"AI 波段投研大脑"的外衣。外衣的布料（组件名、文案措辞、审查文档里的宏大叙事）很好看，但里料（决策公式、prompt 设计、数据源、反馈闭环）完全没有跟着换。**

## 一、方法论：我是怎么下这个结论的

不是凭感觉，逐条给出文件级证据。审查聚焦 4 条主线：

1. **决策引擎语言体系**：决策相关代码里出现的"业务黑话"是什么？（打板黑话 vs 投研黑话）
2. **AI 调用方式**：DeepSeek 被喂了什么输入、允许它想多久、要求它吐多少字？
3. **产业链/基本面模块的连接度**：这些模块写了多少行代码 vs 被多少个地方真正调用？
4. **反馈闭环的通电情况**：AI 说的话、人的操作、事后的盈亏，这三者之间有没有真正打通数据回路？

## 二、核心症结逐项拆解（附代码证据）

### 症结 1：决策引擎的底层语言是"打板"，不是"波段投研"——这是根本性的定位错配

`server/lib/decisionCore.js`（五支柱决策核心 + 游资战术五件套）里的关键函数：

```js
function stageActionOf(stage) {
  const map = {
    冰点: "低吸首板试错(轻仓)", 退潮: "回避接力，管住手", 启动: "打首板/低吸梯队",
    发酵: "接力核心龙头", 高潮: "只持不开，防爆头", 分歧: "高低切，减高位",
  };
  return map[stage] ?? "观望为主";
}

function buyPointOf(stock, cog, sessionPhase) {
  const isAuction = sessionPhase === "竞价" || /09:2/.test(cog?.session?.window ?? "");
  if (isAuction) return "竞价打板/低吸";
  if (stock?.limitUp && (stock?.relay ?? 0) >= 2) return "回封接力";
  ...
  if (stock?.limitUp && (stock?.relay ?? 0) === 1) return "首板打板(需量能)";
  return "盘中分时确认";
}
```

以及 `server/lib/swingStage.js` 里挂着"swing"（波段）名字的阶段模型，判据仍然是"连板高度、涨停、断板、封单"：

```js
function detectFirstBoardDipBuy(bars, limitPct = 9.5) { ... } // 首板次日低吸
function classifySwingPhase(bars) {
  ...
  if (ma5 != null && ma20 != null && price < ma20 && ma5 < ma20) {
    return { phase: "退潮", ... }
  }
  if (biasMa20 != null && biasMa20 > 18) {
    return { phase: "加速", ... } // 偏离MA20达到18%，赶顶风险
  }
  ...
}
```

**问题本质**：
- "买点"的判定条件是"竞价打板 / 回封接力 / 首板打板（需量能）"——这些是分钟级到日级的**打板战术动作**，跟"7 天到数月的波段操作"完全是两套决策频率、两套风险模型。打板要的是"今天封没封住、明天能不能溢价"；波段要的是"这个产业趋势能走多久、这只票在产业链里的位置有没有变化、基本面拐点验证了没有"。
- 复盘窗口全站统一是 **T+1 / T+5**（`decisionAudit`、`decisionPost` 回填逻辑），根本没有"波段仓"应有的 20 日/60 日/季度级复核节奏。一个号称"持股 7 天到数月"的系统，连持仓超过 5 天之后该怎么继续跟踪都没设计。
- "退潮""加速赶顶"这类判据全部基于 MA5/MA10/MA20 短周期均线和涨跌停，**没有任何一处使用财务数据、估值分位、产业景气度作为"要不要继续持有"的依据**。这意味着即使你现在被系统建议"买入"，系统事后也无法回答"这只票为什么值得拿 2 个月"，因为它的记忆里压根没存这些理由。

**根因**：这套系统最早（README 记录的 v3-v4.3）是"A股实时监控终端"，服务于盯盘/打板场景；后续版本号一路涨到 v9.14x，功能越堆越多，但**决策内核（decisionCore/swingStage/mainlineStrength）从未被推倒重来**，新功能都是在打板内核外面挂"AI 分析""产业链""波段"的皮。

### 症结 2：「挖掘产业链」四个字，代码里对应的是 10 条硬编码知识库 + 1 处调用

`src/lib/transmissionChain.ts` 的全部产业链知识库：

```ts
export const CHAIN_KB: IndustryChain[] = [
  { id: "lithium", name: "锂电产业链", nodes: [...4个节点，仅板块名...] },
  { id: "solar", name: "光伏产业链", nodes: [...] },
  { id: "copper", name: "铜产业链", nodes: [...] },
  { id: "semiconductor", name: "半导体产业链", nodes: [...] },
  { id: "steel", name: "钢铁产业链", nodes: [...] },
  { id: "petrochem", name: "石油化工产业链", nodes: [...] },
  { id: "pig", name: "生猪产业链", nodes: [...] },
  { id: "gold", name: "贵金属产业链", nodes: [...] },
  { id: "wind", name: "风电产业链", nodes: [...] },
  { id: "power", name: "电力产业链", nodes: [...] },
];
```

匹配方式是字符串包含/相等（`matchScore`），节点粒度是"东方财富板块名"，**不到个股**、不含营收敞口占比、不含价格弹性系数、不含库存周期、不含供需数据。

调用点核查（全仓库 grep）：

```
src/components/SwingWarRoom.tsx:21: import { assessIndustryCycle } from "../lib/industryCycle";
src/components/SwingWarRoom.tsx:22: import { buildChainView } from "../lib/transmissionChain";
src/components/SwingWarRoom.tsx:405: const score = assessIndustryCycle({...});
src/components/SwingWarRoom.tsx:410: const chain = buildChainView(bd.score.name);
```

**全仓库只有这一处调用**。也就是说：
- AI 助手的"个股深度调研五段式流程"（`src/lib/researchTools.ts` 的 `RESEARCH_SYSTEM`）里 **Phase 3「行业博弈」写的是"researchData/researchSearch 查行业对比/景气/风险"**——完全没有调用已经写好的 `transmissionChain.ts` / `industryCycle.ts`。你花代码写的产业链知识库，AI 做深度调研时根本不知道它的存在。
- 决策卡片（`DecisionVerdictCard`）、选股清单（`StockPickList`）、主线诊断（`MainlineDiagnosisCard`）等所有"拍板"相关的组件，都不引用产业链模块。产业链视图只在"波段作战室"里孤零零显示一张卡片，跟"买不买、买多少、什么时候卖"这三个最终问题没有任何数据连接。
- 覆盖面极窄：10条链只覆盖资源/周期类行业，**消费、医药、TMT 应用层、军工、新能源整车之外的应用场景、出海/跨境电商、AI 应用层等 2024-2026 年真正跑出主线的行业几乎不在库里**；且节点匹配靠字符串包含，"电池"和"电池材料"这种相近词全靠人工写的 `matchScore` 权宜规则，无法应对东方财富板块名的持续变化。

**结论**：这不是"产业链挖掘能力不够强"，而是**产业链模块从设计上就是一个孤立的展示卡片，不是投研大脑的信息骨架**。一个真正"挖掘产业链"的系统，产业链图谱应该是数据库里的一等公民（谁是链主、谁受益、受益比例多少、当前处于链条哪个验证节点），AI 的每一次个股判断都应该先问"这只票在哪条产业链、这条链现在什么状态、这只票在链里能吃到多少"，而现在这套逻辑完全不存在。

### 症结 3：DeepSeek V4 Flash 被系统性"喂不饱"——AI 是格式化工具，不是投研大脑

先看模型接入配置（`src/lib/aiSettings.ts`）：

```ts
deepseek: { label: "DeepSeek V4 Flash", baseUrl: "https://opencode.ai/zen/go/v1/chat/completions",
  model: "deepseek-v4-flash", thinking: false, supportsThinking: true, corsOk: false, ... }
```

再看任务级配置表 `server/lib/aiPrompts.js` 的 `TASK_CONFIG`（共 30+ 个任务）：

- **绝大多数任务 `thinking: false`**：`annRank`、`ladderScan`、`newsDigest`、`mainlineClassify`、`mainlineRank`、`eventExplain`、`themeNewsScore`、`stockNewsScore`、`dailyIntel`、`riskRadar`、`eventClassify`、`agentReason`（ReAct 推理！也是 false）等等——**连"Agent 推理"任务本身都不给模型开思考模式**。
- 只有 `closeReview`、`weeklyCoach`、`stockJudge`、`policyDiff` 少数几个任务 `thinking: true`。
- `maxTokens` 普遍卡在 **2000-3000**（约中文 1000-1500 字），只有 `stockJudge`/`agentReason` 到 8000。

再看 system prompt 的通用铁律（`SYSTEM_PREFIX`）：

```
只输出结论与数字；输出须引用输入的具体数值，禁止"较多/明显"等模糊词；
结论表述采用中性强度词……严格按给定小标题分段，每段不超过3行；语言精悍。
```

以及具体任务模板，例如"梯队把脉"：

```
严格按以下三个标题输出：
【周期定位】当前处于什么阶段（启动/发酵/高潮/退潮），1-2句
【明日看点】≤3条
【断板风险】≤3只
```

**问题本质**：
1. **思考链被系统性关闭**：DeepSeek V4 Flash 是一个"混合推理"模型，支持深度思考（`enable_thinking`），但项目里 24/30+ 的任务显式关闭。而这些任务恰恰是最需要多步推理的（主线归类、事件解释、Agent 推理）。团队自己的代码注释也承认原因是"防止 empty content / 截断"（`llmCore.js` 大段注释在讲 RC-A/RC-B/RC-C 三个历史 bug），也就是说：**开思考容易出故障 → 干脆大范围关闭思考 → 用一个"伪装成推理模型"的模型做纯规则该做的事**。这是拿工程稳定性换掉了产品的核心卖点。
2. **输出被摁死在"3 行小作文"格式**：即使是 `thinking:true` 的任务（比如收盘复盘），最终产出也被 system prompt 限定"每段不超过3行"。深度投研报告需要的是"论证链条"（假设→证据→反证→结论→置信度→触发条件），3 行短句根本装不下一次严肃的产业链传导推理。
3. **"AI 大脑"的核心决策公式完全不用 LLM**：`server/lib/decisionCore.js`（五支柱裁决/游资战术）、`server/lib/reasoning.js`（认知推理层）、`server/lib/swingMainline.js`、`server/lib/mainlineStrength.js` 这些真正决定"买不买、什么时候买、什么时候卖"的模块，**全部是 if-else 阈值判断的纯函数，注释里明确写着"0 LLM token、可回测、永不降级"**。这在工程稳定性角度是对的（规则可控），但意味着：**用户以为的"AI 大脑"其实是一台状态机，AI 只是在状态机吐出结果之后，负责把结果润色成人话**。这是典型的"AI washing"——AI 参与了展示层，没有参与决策层。
4. **个股深度调研虽然有五段式流程，但没有强制产出结构化投研备忘录**：`RESEARCH_SYSTEM` 只是给 AI 一套"建议步骤"，实际输出格式、深度、是否引用产业链数据、目标价测算方法完全靠模型自由发挥，且触发方式僵硬（必须打出"深度调研"四个字），无法对整个自选股/持仓组合批量、定期自动执行。

**结论**：DeepSeek 不是"接不进来"，而是**产品设计上从未打算让它做重任务**。要把 AI 真正用成投研大脑，必须反过来：决策所需的"多因子融合判断"应该交给 AI（在结构化数据支撑下做综合研判），而不是继续用 if-else 算出结论，AI 只负责写稿。

### 症结 4：信息聚合"广度不够、深度更不够"，且跨源数据从未真正"聚合"成证据链

数据源现状（`server/lib/*` + `src/lib/api.ts` 梳理）：

| 类别 | 现有数据源 | 缺失的关键数据源 |
|---|---|---|
| 行情/资金 | 东方财富 push2（行情/资金流/两融/龙虎榜/大宗交易） | 无 |
| 快讯 | 财联社电报（`cls`） | 无其他快讯源交叉验证 |
| 公告 | 东方财富公告 + 关键词分类 | 无结构化提取（重大合同金额、业绩预告具体数字、股权激励行权价等） |
| 基本面 | 东财 F10 财务主数据 + 估值（`fundamentalChecker.js`，阈值体检式，非趋势/非同行对比） | **无研报评级/盈利预测汇总（一致预期）**、无机构调研纪要、无股东户数变化、无高管/大股东增减持、无回购、无限售解禁日历（`earningsCalendar.ts` 只有财报窗口，没有解禁） |
| 产业数据 | 百川盈孚商品现价爬取（91 项大宗商品，无历史序列、无景气指标） | **无行业协会产量/销量/排产数据**（如乘联会、光伏协会、半导体协会）、无出口数据、无价格指数历史曲线（爬到的只是"当日价格快照"） |
| 宏观 | 政策类新闻关键词打标（`policyAnalysis.js`） | 无宏观经济日历（CPI/PMI/社融/美联储议息）、无利率/汇率联动 |
| 海外 | `overseasPatrol.js`（简单巡查） | 无系统化的海外产业链映射（如英伟达财报→国内算力链的传导） |

再看"新闻聚合"的深度（`server/lib/newsAgg.js`）：本质是把不同来源的字段名统一成同一个 JSON 结构（`normalizeSearchArticle`/`normalizeEmwebArticle`/`normalizeKuaixun`），**没有做实体链接、没有做事件去重合并、没有做"多条新闻拼成一条产业逻辑链"的处理**。也就是说，"聚合"目前只做到了"格式统一"，没有做到"信息综合"。

**结论**：即使 AI 推理能力拉满，"巧妙的厨师也做不出没有食材的菜"。现在喂给 AI 的原始信息，广度覆盖不到产业链投研必需的中观（行业产量价格）和微观（机构预期、股东行为）数据，深度也停留在"标题+摘要"级别，没有做跨新闻的因果关联。这是"内容深度不够"这个感受的根本原因之一，而且是比 AI prompt 问题更底层的问题——**先有料，AI 才能出活**。

---

### 症结 5：反馈闭环全线断电，"AI 学习/记忆/协同"是纸面设计

这一条主要引用项目自己的历史审查文档（`022_股票监控项目/审查报告_AI大脑_展示vs协同_2026-08-13.md`），本次审查复核后确认问题性质未变（后续版本号虽然继续增长，但该报告点出的核心断链模式——"写入端从未接线"——是架构层面的通病，不是几个 patch 能治好的）：

- `updateUserProfile()`（AI 学用户风格用的画像更新函数）**全仓库只在测试文件里被调用过**，生产代码从未调用。AI 的 system prompt 里写着"若用户有连亏记录或低胜率题材可下调置信"，但这个"记录"永远是空的——**AI 在自称"参考了你的画像"，但它参考的是一个从未被写过的空文件**。
- `discipline.recordTradeResult()`（连亏熔断纪律）同理，全仓库零生产调用，纪律硬约束永远不会触发。
- 用户对 AI 结论的"否决/忽略"（`watch`/`reject`）只落一条日志，**不会反过来调整任何置信度、任何规则权重**。AI 说错了，AI 不知道，下次还这么说。
- 决策留痕表 `decision_post` 实测仅 5 条记录、`trade_ledger`（真实交易台账）为空表——意味着"AI 决策 vs 实际盈亏"的对照分析、"命中率"统计，全部因为样本量为 0 而显示"样本积累中"的空状态。**一个自称会积累经验的系统，事实上从第一天起就没有真正积累过一次经验。**

这几条不是我推测的，是项目团队自己此前的审查报告发现并写清楚的，本次复核确认：**这类"设计到位、写入端没接线"的模式反复出现（画像、纪律、反馈三处都是同一个模式），说明这是团队开发习惯问题（新功能往往先做"读取+展示"，"写入回路"经常被漏掉或延后），需要在下一阶段开发流程里加硬性检查项。**

---

### 症结 6：功能模块高度孤岛化，"看起来什么都有"是真的，"内容能打通"是假的

审查中反复看到同一种模式：**某个能力被认真实现了（代码质量、纯函数、单测覆盖都不差），但只在一个孤立的入口里被调用，没有被决策主链路复用**。举三个典型：

1. `industryCycle.ts`（景气度评分卡：价格 35% + 资金 30% + 业绩 20% + 政策 15%）——写得比很多模块都规范，四个维度、有信号解释文本、有单测。但只在 `SwingWarRoom.tsx` 一个卡片里出现，**决策卡（DecisionVerdictCard）、选股清单排序、AI 深度调研都不读它**。
2. `commodityPrice.js`（大宗商品价格爬取）——只做了"今天涨跌"快照，**没有存历史序列，没有和 `industryCycle.ts` 的政策分/景气分打通**，理论上"铜价连续上涨 → 铜产业链景气度上调 → 相关个股加分"这条链路技术上是可以做的，但代码里没人把这两个模块接起来。
3. 主线诊断 / 主线回测 / 情绪周期回测（`mainlineBacktest.js`、`stageBacktest.js`）——这些回测模块本身方法论是对的（样本量披露、win rate、次日/3日增量），但**回测的对象仍然是"涨停家数""炸板率"这类打板指标，没有一处回测过"波段策略的持有期收益分布"**（比如"景气度评分>70 分的板块，买入后持有 20/60 个交易日的胜率和盈亏比是多少"）——这才是波段投研真正该验证的问题。

**根因判断**：项目采用了"任务制迭代"（版本号显示已经迭代到 v9.14x，`CHANGELOG.md` 3300+ 行），**每个版本大概率是"加一个新点子的最小实现"，缺少一次"回头把所有模块按统一数据模型串起来"的整合迭代**。这是导致"感觉什么都有、但打不通"最直接的开发流程原因。

---

## 三、根因总结（写给做决策用的你）

把以上六条症结收敛成一句话根因：

> **这套系统的"骨架"（数据模型 + 决策公式 + AI 使用方式）从第一天起就是围绕"游资打板/涨停接力"设计的，后续几十个版本迭代持续往这具骨架上"贴功能、贴皮肤、贴 AI 措辞"，但从未做过一次面向"波段 + 产业链投研"的骨架级重构。所以你看到的是一栋装修得很漂亮、但地基和承重墙还是老结构的房子——不管怎么刷墙纸（加卡片、加 prompt 措辞），房子的用途改不了。**

这解释了你所有的具体感受：
- "华而不实" ← 展示层（卡片、面板、AI 措辞）远远跑在决策层前面
- "内容深度差" ← AI 被摁在短输出、无思考模式、决策核心不用 AI
- "信息聚合几乎没有" ← 数据源本身就窄，且聚合只做了格式统一，没做语义整合
- "无法真正产出决策" ← 反馈闭环断电、复盘周期是 T+1/T+5 短周期、产业链模块不进决策链路
- "AI 嵌入了但用不起来" ← 思考模式被系统性关闭、prompt 把模型能力锁死在"填空题"里
