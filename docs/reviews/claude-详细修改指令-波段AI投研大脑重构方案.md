# stock-monitor 详细修改指令
## 波段 AI 投研大脑重构方案（持仓周期 7 天～数月，产业链驱动，AI 贯穿全局）

> 本文档配合《审查报告-波段AI投研大脑.md》使用。审查报告负责"诊断问题"，本文档负责"怎么改"。
> 面向对象：你自己（或接手开发的人 / AI 编程助手）可以直接把每一章当作任务清单逐条执行。

---

## 〇、总体目标与验收基线

重构完成后，系统必须能对答如流地回答以下 5 个问题，回答不出来就是没做到位：

1. **"这只票现在处于哪条产业链的什么位置？这条链最近发生了什么变化？"**——能秒回，且有数据出处（不是模型自己编的）。
2. **"如果我现在买，理由是什么？打算拿多久？什么情况下我应该认输离场？"**——每次"建议买入"必须自动生成一张包含目标价区间、持有周期、失效条件的决策卡，而不是一句"关注度较高"。
3. **"上周你（AI）说的判断，现在验证得怎么样了？"**——系统要主动追踪自己说过的话，到期自动复盘，而不是等你来问。
4. **"这条产业链/这只票的关键假设有没有被证伪？"**——要有"假设监控"机制，行业数据/公司公告一旦打破原有逻辑要主动预警，而不是被动等你刷新页面。
5. **"你（AI）学到我的哪些偏好/教训了？"**——用户风格画像要真实写入、真实生效、并且要有 UI 可见。

验收方式：不看代码量，看能不能拿一只真实股票（比如"某锂电池中游材料厂"）把上面 5 个问题连续问一遍，系统全部给出有数据支撑的回答。

## 一、产品重新定位（决定后面所有技术决策的前提）

### 1.1 明确"波段投研大脑"的决策频率分层

不要再用"打板"的单一时间尺度思考问题。重构后要显式区分三层节奏，并在数据模型和 UI 里都体现出来：

| 层级 | 决策周期 | 核心问题 | 主要数据 |
|---|---|---|---|
| L1 产业景气层 | 周～季度 | 该不该关注这条产业链/这个行业 | 产量价格数据、政策、财报周期、库存周期 |
| L2 个股基本面层 | 周～季度 | 这只票在产业链里能吃到多少、质地好不好 | 财务三表、机构预期、股东行为、估值分位 |
| L3 波段择时层 | 天～月（对应你说的 7 天～数月） | 现在是不是好的买卖点、仓位多少、止损在哪 | K线阶段、资金流、消息催化、情绪面 |

现有代码里 90% 的能力都堆在 L3（且是 L3 里最短周期的打板战术），L1、L2 几乎是空的或者孤岛化的。重构的核心工作量应该反过来：**优先补 L1、L2，再把 L3 现有能力接进来做"择时扳机"，而不是让 L3 继续主导一切。**

### 1.2 决策产出物统一规格：「波段投研决策卡」

废弃现在分散的"决策卡/裁决卡/主线诊断卡"多套并行输出格式，统一为一张结构化决策卡（数据库表 + UI 组件 + AI 生成模板三处同步），字段规范如下：

```
{
  code, name,
  chain: {                     // 产业链定位（第三章新增能力）
    chainId, chainName, nodeRole,           // 该股在产业链中的角色：资源/材料/设备/制造/应用/渠道
    upstream: [...],  downstream: [...],
    exposurePct,                             // 该业务在公司营收中的占比（有数据则填，无则标注"未披露/估算"）
    chainStage,                              // 该产业链当前所处周期阶段：导入期/放量期/成熟期/出清期
    chainSignals: [...]                      // 支撑上述判断的具体证据（价格数据/政策文件/协会数据，带来源和日期）
  },
  fundamentals: {               // 基本面（第四章新增能力）
    qualityScore, valuationPercentile,       // 质地分、估值历史分位
    catalysts: [...],                        // 未来 60-180 天的确定性事件（财报窗口/解禁/回购/新品发布）
    risks: [...]
  },
  timing: {                     // 波段择时（复用+改造现有 L3 能力）
    stage,                                    // 复用 swingStage 阶段模型（但要重新校准，见4.4）
    entryZone, stopLoss, targetZone,
    holdingHorizonDays,                       // 预计持有周期（7-20 短波段 / 20-60 中波段 / 60-180 长波段）
    positionSizeSuggestion
  },
  thesis: {                     // 投资论证链（AI 生成，第五章重点）
    coreLogic,                                // 一句话核心逻辑
    evidenceChain: [...],                     // 支撑证据（每条标注来源+时间，禁止无来源结论）
    invalidationConditions: [...],            // 假设失效条件（第六章的假设监控依据）
    confidence, reviewCycleDays              // 置信度 + 下次强制复核间隔
  },
  provenance: { generatedBy, model, thinkingUsed, tokensUsed, asOf }
}
```

这张卡是本次重构"看得见的验收物"。第三～六章的所有改造都是为了能把这张卡的每个字段填真实、填对。

## 二、工程基础修复（P0，必须先做，否则后面白改）

在动"大脑"之前，先把已知拖后腿的数据管道问题清干净，参考项目自己此前审查报告已定位的问题（复核仍然有效）：

1. **cron 表达式秒/分混淆问题**：检查所有 `cron.schedule(...)` 表达式字段数与 `node-cron` 版本语义是否匹配（6 字段=含秒位），特别是盘中高频任务，确认不会以秒级频率抢占数据库锁。
2. **收盘主链作用域 bug**：检查 15:40 收盘链条里变量声明作用域（如 `dateStr`）是否跨 `try` 块被引用，修复后要有"链路完整跑通"的自检落库标记（`cron checkpoint`），而不是靠日志肉眼确认。
3. **Agent 记忆工具鉴权失败**：检查内部 API 网关白名单路径匹配是相对路径还是绝对路径，确保 Agent 的本地数据检索工具（新闻/公告/龙虎榜/调研库查询）真正能拿到数据，而不是恒定 401 静默失败后走"降级"掩盖问题。
4. **LLM 网关可靠性**：把"空响应率""超时率""截断率"做成可观测指标（接入 `/api/health` 或专门的监控面板），设定阈值告警，而不是任由用户在使用中"随缘遇到规则版兜底"。
5. **反馈闭环写入端补全**（这是本次审查发现的最关键工程债）：
   - 用户拍板（买/卖/观望/否决）后，必须真实调用画像更新函数，把这次操作、这次操作的理由标签、事后 T+N 的盈亏，写入用户画像表。
   - 连续亏损/连续错误采纳建议后，必须真实触发纪律熔断（降低建议仓位、提示冷静期），而不是只在文档里写"有这个机制"。
   - 决策卡片需要新增"👎 这个判断不对，因为___"的结构化反馈入口（预置选项：产业链判断错/基本面判断错/择时判断错/数据本身错），反馈要真实写回该决策的置信度记录，供后续统计"AI 在哪一层最容易犯错"。

验收标准：连续跑 5 个交易日，产出一份《数据管道健康报告》，包含各 cron 任务实际执行时间/是否完整、LLM 调用成功率、反馈写入笔数（要求 >0 且逐日增长），三项全部达标才能进入下一阶段。

## 三、产业链知识图谱重构（这是"挖掘产业链"能不能成立的核心）

### 3.1 从"硬编码 10 条数组"升级为"数据库化的产业链图谱"

新建数据表（Drizzle schema 思路，字段名可按实际习惯调整）：

```
industry_chain            链主表：id, name(如"锂电产业链"), description, updated_at
industry_chain_node       节点表：id, chain_id, name(如"中游电池制造"), node_role(资源/材料/设备/制造/应用/渠道), sequence(上下游顺序)
industry_chain_node_stock 节点-个股映射表：node_id, stock_code, exposure_pct(该业务营收占比，可空), role_note, source, confirmed_at
industry_chain_signal     节点信号表：node_id, signal_type(价格/政策/产量/库存/新闻), value, unit, direction(涨/跌/持平), effective_date, source_url
industry_chain_event      传导事件表：id, chain_id, origin_node_id, title, summary, published_at,
                           impact_path(JSON：记录AI推理出的传导路径，如"上游锂价上涨→中游材料厂成本压力→关注是否有提价能力"),
                           impacted_nodes(JSON数组), confidence, model_generated(bool)
```

### 3.2 节点-个股映射：从"板块名匹配"升级为"个股级别、带营收敞口"

现状（`transmissionChain.ts`）节点只到"东财板块名"，必须升级为**具体到个股代码**，并尽量标注该业务在公司营收中的占比。数据来源建议：
- 优先用已有的东财 F10 主营构成接口（`PLATE_FEATURE_MAIN` / `CWFX_MAINQUERY` 一类主营业务构成数据），可解析出"某公司主营构成"，作为 `exposure_pct` 的数据源。
- 没有官方主营构成数据的，允许 AI 基于研报/公告摘要给出估算敞口，但必须标注 `confirmed_at = null` / `source = "AI估算，未经人工确认"`，UI 上要有明显的"未核实"标签，防止误导。
- 建立"人工/AI 协同标注"流程：AI 生成候选映射 → 人工在 UI 上一键确认/修正 → 确认后的映射才进入决策卡引用范围。这比一次性想把全市场都标注完更现实。

### 3.3 产业链覆盖面扩容

10 条链严重不足，第一阶段至少扩到 **40-50 条**，覆盖当前 A 股主要热点产业方向，包括但不限于：AI 算力硬件链、AI 应用/端侧 AI 链、机器人链、创新药/CXO 链、军工链（无人机/低空经济）、消费出海链、白酒/大众消费链、券商/金融科技链、数据要素/信创链、新能源整车/智能驾驶链等——**不是一次性穷举，而是要建立"新链发现流程"**：当某个板块连续多日成为资金/新闻焦点但不在知识库中时，触发人工/AI 协同建链任务（AI 起草上下游节点草稿 → 人工确认）。

### 3.4 价格/产量数据源扩容（喂给产业链的"料"）

现有 `commodityPrice.js` 只抓"当日快照"，需要升级为：
- 落库历史序列（`industry_chain_signal` 表按日期存），能算出"MA20/MA60/同比/环比"等趋势指标，而不是只有一个瞬时值。
- 补充免费可得的行业协会/统计口径数据（示例，需按实际可抓取性调研）：乘联会/中汽协新能源车月度销量、光伏协会月度排产、中国半导体行业协会数据、国家统计局 PMI 分项、海关总署进出口分产品数据。这些数据更新频率是周/月级，正好匹配"波段"的决策节奏，抓取压力远小于高频行情数据。
- 每次抓到新数据，自动生成一条 `industry_chain_signal`，并触发第五章的"传导推理 Agent"评估是否需要更新相关节点个股的决策卡。

### 3.5 打通"产业链"与决策主链路（解决"孤岛化"问题，这一步最关键）

审查报告指出的核心问题是"写了但没人调用"。本次重构必须做到：
1. **AI 深度调研的 Phase 3「行业博弈」，代码层面强制先查询 `industry_chain_node_stock` 表，找到该股所在产业链和节点，再基于该链的 `industry_chain_signal` 最新数据生成分析**，不能再是自由的开放式搜索。
2. **决策卡生成时，`chain` 字段必须从数据库真实查询填充**，查不到映射就诚实显示"未收录，待补充"，而不是留空或跳过。
3. **选股清单排序新增"产业链景气度"作为可选排序维度**，让景气度评分（`industryCycle.ts`，需要接入真实的产量价格数据后重新校准权重）真正参与选股，而不是只在一个孤立卡片里自娱自乐。

## 四、个股基本面层补强（L2，波段投研的地基）

### 4.1 从"阈值体检"升级为"趋势 + 同行对比"

现有 `fundamentalChecker.js` 是静态阈值判断（ROE≥8%、负债率≤60%……），对波段投研意义有限。需要新增：
- **环比/同比趋势**：至少展示最近 8 个报告期的 ROE/毛利率/营收增速/净利增速趋势线，判断"业绩拐点"比判断"当前是否达标"更重要。
- **同行业对比分位**：拉取同一产业链节点/同一申万行业的可比公司，计算该股在估值（PE/PB/PS 分位）、盈利能力上的行业排位，而不是孤立看一只票的绝对数值。
- **一致预期/机构评级**（如可获得数据源）：接入研报评级数量、评级变化趋势（上调/下调家数），作为"业绩兑现预期"的补充证据。

### 4.2 新增关键事件日历，作为"催化剂时间表"

新建 `catalyst_calendar` 表，统一管理会拉动股价的确定性/半确定性事件：财报披露窗口（已有）、限售解禁日期（需新增）、股权激励行权/解锁条件、回购计划进度、定期的行业展会/发布会。决策卡的 `fundamentals.catalysts` 字段直接查询这张表，按未来 7/30/90/180 天窗口展示，这是"持仓 7 天到数月"期间用户最需要盯的东西，现有系统完全没有。

### 4.3 新增股东行为信号

接入十大流通股东变化、大股东/高管增减持公告、机构调研纪要出现频次，这些是波段投资中判断"聪明钱在不在场"的关键信号，比现有的"龙虎榜游资席位"（更偏打板）更贴合波段/产业链投资逻辑。

## 五、AI 投研大脑重新设计（让 DeepSeek 真正"贯穿全局"）

这是解决"AI 嵌入了但用不起来"这一核心诉求的章节，也是本次重构工作量最大、价值最高的部分。

### 5.1 架构：从"单点调用"改为"分层 Agent 流水线"

不要让每个前端交互各自拼一次 prompt 去调用模型（现状），改为服务端常驻的分层 Agent 流水线，职责分离、结果落库、可追溯：

```
① 数据整备 Agent（0 token，纯规则/ETL）
   → 汇总某只股票/某条产业链的结构化原始数据（行情/财务/资金/新闻/产业信号）

② 产业链传导推理 Agent（LLM，thinking=true，任务专属，非通用聊天）
   → 输入：产业链最新信号 + 该链所有节点个股列表
   → 输出：传导路径推演（如"碳酸锂价格连续3周反弹 → 材料厂成本压力缓解 → 关注有库存/长协优势的中游公司"）
   → 落库为 industry_chain_event，供后续所有个股决策卡引用（一次推理，多只票复用，大幅降低 token 成本）

③ 个股基本面研判 Agent（LLM，thinking=true）
   → 输入：财务趋势 + 同行对比 + 催化剂日历 + 股东行为 + ②的产业链推理结论
   → 输出：质地评分 + 估值判断 + 未来60-180天关键验证点

④ 波段择时 Agent（LLM，thinking=false 可接受，因为择时更依赖量化规则，AI 负责综合多规则信号做"排除法"式判断而非重新发明规则）
   → 输入：现有 swingStage/资金面/情绪面规则输出 + ②③的结论
   → 输出：买卖点建议 + 仓位建议 + 止损位

⑤ 决策卡合成 Agent（LLM，thinking=true，唯一负责"写报告"的环节）
   → 汇总②③④结果，生成第一章定义的完整《波段投研决策卡》，包含 evidenceChain（每条结论标注来自②③④哪一步、依据哪条原始数据）

⑥ 复盘/假设监控 Agent（定时任务触发，见第六章）
```

**核心原则**：不是让 AI 从头脑一次性想出所有答案（那样既不可控也不可追溯），而是让 AI 在每一层结构化数据支撑下做"这一层"的专业判断，层与层之间的中间结论要落库、要可追溯来源。这样即使某一层输出不理想，也能定位到具体哪个 Agent 环节需要调优，而不是像现在这样"整个 AI 助手时好时坏，出问题不知道哪里错的"。

### 5.2 DeepSeek 使用规范：把"深度思考"用在真正需要深度的地方

- **② 产业链传导推理、③ 基本面研判、⑤ 决策卡合成三个环节，`enable_thinking` 必须为 `true`，且 `max_tokens` 不低于 6000-8000**。这三步是真正需要多步推理、交叉验证的地方，不能再用"分类器模式"打发。
- ④ 波段择时环节可以保留 `thinking:false`（因为择时更适合"综合已有规则信号 + 排除法判断"，属于相对确定性任务，用小快模型即可，省 token）。
- 明确区分"格式化/分类小任务"（新闻打标、快讯摘要、公告评分）继续用 `thinking:false` 的原有模式——**这些任务本来就不需要深度思考，不用因为"要重视 AI"就一刀切全开思考**，关键是把思考力度用在刀刃上（产业链推理、基本面综合判断、最终决策合成），而不是平均分配。
- 废除"每段不超过 3 行"的通用铁律对②③⑤三个环节的限制，改为**结构化 JSON 输出 + 每个结论字段必须附带 `evidence`（引用哪条原始数据/日期/来源）**，避免"空泛结论"，同时用 JSON schema 校验保证仍然是可控格式（不是放任模型写小作文）。
- 引入"批量+复用"机制降低成本：产业链传导推理（②）按"链"为单位而不是按"股票"为单位触发，一条链算一次，链上所有个股复用同一份传导结论，这样即使把 thinking 打开、token 用足，总调用量也是可控的（50 条链 vs 5000 只个股，两个数量级的差异）。

### 5.3 深度调研流程改造：从"用户手动触发的单次对话"变成"系统化、批量化的持续研究"

- 五段式深度调研的 Phase 3「行业博弈」必须接入 3.5 节的产业链数据库查询，不能再是自由搜索。
- 新增"自选股/持仓组合批量深度调研"：不要求用户逐个手打"个股深度调研 XXX"，而是对用户自选股/当前持仓，按设定周期（如每周一次，或产业链有重大信号变化时触发）自动跑一遍五段式流程，生成/更新决策卡，用户打开系统就能看到"自动更新的最新判断"，而不是每次都要主动发起对话。
- 输出的调研结论要固定写入决策卡的 `thesis` 字段，历史版本要保留（不能每次覆盖），这样才能在第六章做"假设是否被验证"的比对。

### 5.4 波段择时模型重新校准（复用现有代码，但要改判据）

`swingStage.js`/`swingMainline.js` 的均线/连板判据可以保留作为"择时子信号之一"，但需要新增：
- **成交量/换手率的中周期（20-60日）趋势**而不仅是单日量比，判断资金是否处于"持续吸筹"还是"脉冲式炒作"。
- **回撤容忍度按 `holdingHorizonDays` 分层设置止损**：短波段（7-20天）用较紧止损（如破位 20 日线），中长波段（60-180天）用更宽的止损带（如破位 60 日线或产业逻辑证伪），现有系统止损纪律是"一刀切"的短线止损逻辑，完全不适配数月级别的持仓。
- 明确废弃"打首板/竞价打板/回封接力"这类纯打板战术判据在"波段模式"下的默认展示优先级——可以保留作为"激进/短线模式"的可选项，但"波段投研大脑"的默认视角应该优先展示"低吸/回踩/突破加仓"这类适合中长周期建仓的判据。

## 六、决策与复盘周期改造（匹配"7天～数月"的真实节奏）

### 6.1 废除单一 T+1/T+5 复盘窗口，改为"周期分层复盘"

- 短波段仓位（`holdingHorizonDays` ≤ 20）：T+1、T+5、T+10 三档回填。
- 中波段仓位（20-60天）：T+5、T+20、T+40 三档回填 + 20日强制复核提醒。
- 长波段仓位（60-180天）：T+20、T+60、T+120 三档回填 + 60日强制复核提醒 + 每次财报窗口后强制复核。

### 6.2 新增"假设失效监控"（Thesis Invalidation Monitor）——这是波段投研区别于打板监控最核心的机制

每张决策卡在生成时必须写明 `thesis.invalidationConditions`（如"若碳酸锂价格连续两周跌破XX元/吨，则本次判断的成本逻辑失效"、"若下一期财报毛利率环比下滑超过3个百分点，则质地判断需要重新评估"）。系统需要新增定时任务：
- 每日/每周扫描所有持仓中票的 `invalidationConditions`，用最新数据（产业链信号、财报数据、股价行为）逐条核对，一旦触发，**主动推送预警**（不是等用户来问），并自动生成"复核建议"，供用户决定是否调整仓位。
- 这条机制直接对应审查报告里"AI 主动推送靠谱不靠谱"的问题——现有系统的"主动推送"是基于情绪/异动的日内事件，重构后要新增"基于产业链和基本面假设是否被证伪"的中长周期主动预警，这才是波段投资者真正需要 AI 帮忙盯的事。

### 6.3 组合级别的复盘，而不只是单只个股复盘

新增"持仓组合周期报告"（周报/月报，AI 生成，thinking=true）：本周期内持仓的产业链归因（哪条链贡献了收益/亏损）、假设验证情况汇总、下一周期的关注清单调整建议。这比现有的"周报教练"（只看纪律执行率、重复错误模式）更贴近波段投资者需要的"组合体检"。

## 七、用户画像与协同闭环补线（把审查报告发现的"假闭环"改真）

1. `updateUserProfile()` 必须在拍板确认（买入/卖出/加仓/减仓操作确认）后被真实调用，写入：操作类型、当时决策卡的完整快照、T+N 后的实际盈亏、用户是否遵循了 AI 建议的止损位。
2. 新增「我的画像」页面（不是隐藏在设置里的一行文字），展示：AI 学到的交易风格标签、历史上判断准确率最高/最低的产业链方向、容易复现的行为偏差（如"经常在止损位不止损""偏好追高热点链"）、当前纪律状态（是否处于连亏冷静期）。
3. 决策卡新增结构化反馈按钮（👍准确 / 👎不准确，选择错误归因：产业链判断/基本面判断/择时判断/数据错误），反馈数据进入画像统计和 AI 置信度校准，形成"用户纠正 → 系统记住 → 下次同类判断自动降权"的真实回路。
4. 纪律熔断规则真实触发：连续 N 次（如3次）实际亏损或连续 N 次否决 AI 建议后仍自行操作导致亏损，系统自动将新建议的建议仓位下调、并在决策卡顶部提示"冷静期"，而不是永远停留在"lossStreak 恒为 0"的状态。

## 十二、附：产业链传导推理 Agent 的 Prompt 设计示例（可直接作为起点）

```
System:
你是产业链研究员，基于给定的产业链结构和最新价格/政策/新闻信号，推演本轮变化会如何沿产业链传导，
并指出受益/受损的具体环节。你的每一条结论必须引用输入中的具体数据点（数值+日期+来源），
禁止使用"可能""或许"等无依据的猜测性表达；如果证据不足以支撑某个传导判断，直接说明"证据不足，暂不判断"。
输出必须是结构化 JSON，不要输出额外文字。

User:
产业链：{chainName}
节点结构（上游→下游）：{nodes}
最近14天信号：
{industry_chain_signal 列表，含日期/类型/数值/方向/来源}
最近14天相关新闻/政策：
{news 列表}

请输出：
{
  "impactPath": "一句话概括本轮变化的传导路径",
  "impactedNodes": [
    { "node": "节点名", "direction": "受益/受损/中性", "reasoning": "引用具体数据的推理过程", "confidence": 0-100, "evidence": ["数据点1（来源+日期）", "数据点2"] }
  ],
  "watchPoints": ["接下来2-4周需要验证的关键数据点，每条注明预计公布时间"],
  "invalidationCondition": "什么情况发生会证明上述传导判断是错的"
}
```

这个模板的关键设计原则（务必保留）：**强制要求 evidence 引用、强制允许"证据不足不判断"、输出格式结构化但内容不限行数**——这三点直接对应审查报告里"AI 输出空泛、无法产出决策"的病根。

## 十三、一句话给执行者

不要再往现有的打板决策引擎上"加功能""加卡片""加 AI 措辞"。这次要做的是：**先把产业链和基本面的数据地基铺好，再把 AI 从"结果润色器"提升为"数据充分支撑下的分层研判者"，最后把决策、反馈、复盘三个环节的电线真正接通**。骨架不换，功能加得再多也还是那台"披着 AI 外衣的打板终端"。
