## 一、上一段复盘的 3 个断层 → v9.39 实证核查（先认账，再挑刺）

### 断层 1：AI 是"手动按钮"不是"主导者" → ✅ 已修（表层）
**对话原文**：`Dashboard.tsx` 有个 `<button onClick={runAgent}>`，不点 AI 不跑；DecisionVerdictCard 0 行 AI。
**v9.39 实证**：
- `Dashboard.tsx` 新增 `useEffect(()=>{...setTimeout(()=>runAgent(true),1500)},[battlePlan])` —— **主线数据更新后自动触发 Agent**（5 分钟节流）。✅ 不再依赖按钮。
- `DecisionVerdictCard.tsx:34-36`：`aiVerdict = agent && !agent.degraded ? agent : null; mainAction = aiVerdict?.action ?? verdict?.action` —— **AI 裁决可用时覆盖规则结论**，并置顶大号显示（"🤖 AI 决策（自动主导）"），规则投票折叠进 `<details>` 证据区。✅ AI 置顶。
- **结论：断层 1 表层已修。** 你现在打开页面会看到 AI 自动出裁决。

### 断层 2：幻方闭环断开 → ✅ 已接（接线层）但 ⚠️ 被绕过（见 V4-B）
**对话原文**：factorLib 的 IC 算了没接 decisionBus；Dashboard 没传 signalGates，门控空转。
**v9.39 实证**：
- `decisionBus.ts` 已有 `opts.factorStats`（失效因子占比→置信下调）和 `opts.signalGates`（胜率门控）。✅
- `Dashboard.tsx:583-697`：`signalGates` 取自 `backtestSignals(14)`，`factorStats` 取自 `factorLib.evaluateAllFactors`，并落库 `factor_ic:日期`，二者**都传给了 DecisionVerdictCard**。✅
- `DecisionVerdictCard.tsx:30`：`runConsensus(sources, { signalGates, factorStats })` —— **门控真正喂进了 runConsensus**。✅
- **结论：断层 2 的"接线"已通。** 但⚠️ 它只作用于**规则投票那条路**，而 AI 路径会覆盖它——详见第二节 V4-B。

### 断层 3：样本量撑不起"越用越准" → 🟡 部分缓解（硬约束）
**v9.39 实证**：cron 新增**盘中每小时**落 `market_intraday:日期`（v9.38），样本从每日 1 条→每日多条。✅ 方向对。

- **结论：样本问题从"天数少"变成"字段缺"——10 个因子里有 4 个永远算不出 IC。** 见 V4-G。

## 二、🔴 V4 核心发现：AI 主导是"表"，内核仍是规则复读机

> 这是 V4 最重要的结论。它解释了"为什么 UI 变了、你还是觉得 AI 没主导"。

### 发现 A：所谓"Agent"不是智能体，是"规则打包器 + LLM 摘要器"

**证据**：`aiAgent.ts` 第 3 行自承——
> `// 不依赖原生 tool_calls 协议（callAI 为单轮），采用务实编排`

实际流程（`runDecisionAgent`）：
1. `collectToolEvidence(ctx)`：**无条件**把 13 个规则工具全跑一遍（0 次 LLM），把每个规则的结论打包成 `{name, verdict, confidence}`。⚠️ LLM **不决定**调用哪个工具、**不观察**中间结果。
2. `adjudicateOnce`：**1 次** LLM 调用，把上面的证据包拼成文本喂给 Agnes，让它输出 `{action, confidence, reason}`。**这是单轮一次性**。
3. `criticReview`：**可选** 1 次"挑刺"调用（默认 Dashboard 没开 `useCritic`）。

**问题本质**：
- LLM 拿到的是**规则的结论**（"准入闸：可上车；诱多引擎：观望"），不是**原始盘面数据**（封单 8 亿、炸板 3 次、席位净买 2 亿）。
- 既然喂的是结论，AI 能做的只有"复述 + 润色"——它**没有独立信息源**去推翻规则。规则错了，AI 就跟着错。
- 这不是"AI 替代决策"，是"**AI 给规则的投票结果写一段解说词**"。GLM5.2 要的"AI 主动调研→证伪→出单"，这里只完成了"出单"那一步，且出单的依据还是规则的。

**对比真智能体应做的**（V4-A 要补的）：
- LLM 拿到**原始数据**（涨停池/封单/席位/资金流原文）
- LLM **自主决定**先查什么（"先看这条主线有没有龙虎榜加持"→调 `getLhbCross`）
- 观察→再决定（"加持了，再验证封单稳不稳"→调 `detectSealDecay`）
- 多步后才出裁决

### 发现 B：幻方门控被 AI 路径绕过（接线通了但没接到出结论的路上）

**证据链**：
1. `DecisionVerdictCard.tsx:30`：`verdict = runConsensus(sources, {signalGates, factorStats})` ← **规则路径**用了门控 ✅
2. `DecisionVerdictCard.tsx:35`：`mainAction = aiVerdict?.action ?? verdict?.action` ← **AI 可用时直接覆盖**，mainAction 取 AI 的
3. `aiAgent.ts adjudicateOnce`：构造裁决时**完全没读** signalGates / factorStats；Agent 自己的证据权重写死 0.8（`collectToolEvidence:40`）

**后果**：当 Agent 跑通（现在默认自动跑），最终展示的 `mainAction` 来自 AI，而 AI 没受幻方门控约束。**于是你精心接上的"因子失效→降权"只影响被折叠隐藏的规则投票，不影响真正显示的结论。** 这就是"幻方闭环接通了但你感受不到"的原因。

### 发现 C：AI 静默覆盖规则分歧，无告警（替代决策的危险信号）

**证据**：`mainAction = aiVerdict?.action ?? verdict?.action` —— 当 AI 说"可上车"、规则门控说"禁止"（比如因子失效/诱多），**AI 静默胜出，用户看不到分歧**。
**后果**：这恰恰是"替代决策"最该防的——AI 自信地指错路而你不知情。GLM5.2 强调的"多重交叉验证避免错误方向"，在"AI 一票覆盖"下被削弱。

### 发现 D：`collectToolEvidence` 的 verdict/confidence 映射脆弱

**证据**（`aiAgent.ts:34-35`）：
```ts
const verdict = String(obj.action ?? obj.state ?? obj.level ?? "观望");
const confidence = Number(obj.confidence ?? obj.positionFactor ?? 50) * (typeof obj.confidence === "number" ? 1 : 100) || 50;
```
- 不同工具返回结构不同（有的是 `{action}`、有的是 `{state}`、有的是 `{level:"red"}`、有的是 `{positionFactor:0.6}`），用 `??` 兜底 + 乘 100 的逻辑**既容易错位也容易把 0.6 算成 60 又或把 80 误处理**。`level:"red"` 会被当 verdict 字符串。这是埋雷。

### 发现 E：Agent 只裁决 `candidates[0]`（单一主线）
**证据**：`Dashboard.tsx runAgent`：`const top = battlePlan?.candidates?.[0]; ... decideForMainline(top,...)`。只对最强主线出 AI 裁决，第 2、3 主线无 AI 结论。

### 发现 F：`https-proxy-agent` 仍未声明依赖（V1 P0-1 的尾巴）
**证据**：`server/lib/httpProxy.js` 已改成惰性 + try/catch（**不再崩溃**，V3-P0 的"部署即崩"已解 ✅），但 `server/package.json` **仍然没有** `https-proxy-agent`。
**后果**：干净环境能启动（不崩），但**代理模式静默降级直连**——在需要 Clash 代理访问 apihub 的环境里，AI 会"看起来配了 Key 却全超时"，且无显眼报错。

## 四、V4 修改指令（最后一公里，让"AI 主导+幻方"从表到里）

### 🔴 P0：让 AI 真的"主导"（不再是规则复读机）

#### 【V4-A】把 Agnes 升级为真·工具调用智能体（native tool_calls）
- **文件**：`src/lib/aiAgent.ts`、`server/routes/ai.js`、`src/lib/ai.ts`
- **根因**：当前 `adjudicateOnce` 把"规则的结论"喂给 LLM，AI 只能复述。
- **改法**：
  1. 在 `server/routes/ai.js` 的 `/api/ai/call` 增加 `tools`/`tool_choice` 透传（Agnes 走 OpenAI 兼容 `/v1/chat/completions`，原生支持 `tools` + `tool_calls`）。
  2. `aiAgent.ts` 改为真 ReAct 循环：第 1 轮把**原始盘面摘要**（涨停池/封单/资金原文，不是规则结论）+ 工具清单给 LLM → LLM 返回 `tool_calls` → 本地执行 → 结果回灌 → 循环至 LLM 给出最终裁决或达轮次预算（≤5）。
  3. 关键：**LLM 决定调用顺序**，而不是无条件全跑。例如 LLM 可能先 `checkSysRisk`，发现 red 就直接"禁止"提前结束。
- **验收**：给定一个带诱多的样本，AI 能自主先调 `detectTrap` 再调 `getLhbCross` 得出与规则不同（更准）的结论；日志能看到多轮 tool_calls。

#### 【V4-B】让幻方门控真正约束最终结论（修"绕过"）
- **文件**：`src/lib/aiAgent.ts`、`src/components/DecisionVerdictCard.tsx`
- **根因**：AI 裁决覆盖规则，但 AI 不消费 factorStats/signalGates。
- **改法（二选一）**：
  - 方案 1（推荐）：最终结论 = `fuse(aiVerdict, ruleVerdict)`。当 `factorStats.decayed/total ≥ 0.5` 或某关键信号被门控时，**即使 AI 说"可上车"也强制下调一档（→观望）并标注"🧪 因子失效门控下调"**。
  - 方案 2：把 `factorStats`/`signalGates` 注入 Agent 的 prompt，让 LLM 自己感知"当前因子可信度低"，并在 evidence 里体现。
- **验收**：构造因子大面积失效的场景，AI 即便判"可上车"，最终展示为"观望+门控标注"。

### 🟠 P1：交叉验证的"可见性"与"防错"

#### 【V4-C】AI-规则分歧显式告警（不静默覆盖）
- **文件**：`DecisionVerdictCard.tsx`
- **改法**：当 `aiVerdict.action !== verdict.action` 时，顶部加红/黄横幅"⚠ AI 与规则多源分歧：AI=X / 规则=Y，建议人工复核"，并把两边理由并列。**绝不让 AI 静默压过规则的反对**。
- **验收**：AI=可上车/规则=禁止时，横幅出现且不直接显示"可上车"为最终结论。

#### 【V4-D】默认开启 Critic + 自洽投票（可控成本）
- **文件**：`Dashboard.tsx runAgent`
- **改法**：`runDecisionAgent(ctx, { useCritic: true, selfConsistency: false })`——至少开 Critic（多 1 次调用，挑刺价值高）。自洽投票默认关可接受，但**高置信决策**（AI 说"可上车"且 confidence≥75）应自动开一次自洽复核。
- **验收**：高置信"可上车"前必过 Critic。

#### 【V4-E】Agent 覆盖 Top-3 主线
- **文件**：`Dashboard.tsx`、`DecisionVerdictCard.tsx`
- **改法**：`decideForMainline` 对 `candidates.slice(0,3)` 各跑一次（5 分钟节流共享），裁决卡展示 Top 主线的 AI 结论 + 其余两条的一行摘要。
- **验收**：第 2、3 主线也有 AI 裁决（哪怕简版）。

### 🟡 P2：工程收尾与数据基础

#### 【V4-F】修 `collectToolEvidence` 脆弱映射
- **文件**：`aiAgent.ts:34-35`
- **改法**：每个工具 execute 返回**统一 schema** `{ verdict: Verdict, confidence: 0-100, reason }`，由工具自身负责归一（如 `level:"red"→verdict:"禁止"`），消除 `??` 链 + 乘 100 的脆弱逻辑。
- **验收**：所有工具返回统一 schema；单测覆盖映射。

#### 【V4-G】补齐因子输入字段（修 4 个永远失效的因子）
- **文件**：`server/cron.js`（market_daily 落库）、`factorLib.ts`
- **根因**：`sealDecayCount/lhbBoostCount/fundInflowStreak/nuclearCount` 在 `market_daily` 没落库 → 4 因子永远 null → 永远 decayed。
- **改法**：cron 15:40 落 `market_daily` 时，额外聚合当日"封单衰减预警数/龙虎榜加持涨停数/主线行业连续流入天数/核按钮数"一并写入；前端 `loadFactorRows` 一并读取。
- **验收**：这 4 个因子的 `samples ≥ 5` 后能算出真实 IC（不再恒 decayed）。

#### 【V4-H】补 `https-proxy-agent` 依赖（V1 遗留尾巴）
- **文件**：`server/package.json`
- **改法**：`dependencies` 加 `"https-proxy-agent": "^7.1.0"`。惰性容错保留（双保险）。
- **验收**：干净 `npm install` 后，代理模式能正常创建 `HttpsProxyAgent`（不再静默降级直连）。

#### 【V4-I】数据不足时强制降级提示
- **文件**：`DecisionVerdictCard.tsx`
- **改法**：当 `factorStats.total < 3` 或回测样本普遍不足时，AI 裁决卡显式标注"⚠ 历史样本不足（N 天），AI 结论仅参考，不构成高置信决策"。
- **验收**：样本不足时提示可见，避免"数据不够却高置信"的误导。

## 六、给你的诚实复盘（为什么"没看到效果"）

你上一次的直觉完全正确，原因不是团队没努力，而是**做了"形"没做"神"**：

1. **"AI 自动跑+置顶" ≠ "AI 主导"**：自动跑的是"规则打包→LLM 摘要"，LLM 没有独立信息源，只能复述规则。要让 AI 真主导，必须给它**原始盘面 + 自主调工具的能力**（V4-A）。
2. **"门控接线通了" ≠ "幻方闭环转起来"**：接线只通到规则投票那条路，而那条路被 AI 覆盖了。要让幻方真起作用，门控必须**作用到最终展示的结论**上（V4-B）。
3. **数据基础**：4 个因子因字段缺失永远失效，10 因子实际只有 6 个能算 IC（V4-G）。

**所以现状是：你看到 AI 在自动出结论，但那个结论本质是规则投票的"翻译版"；你看到幻方门控代码都在，但它管不到真正显示的结论。** V4 就是把这两件事从"形"做到"神"。
