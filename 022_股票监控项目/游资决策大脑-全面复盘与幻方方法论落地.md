## 二、关键问题与解决方案（战役级复盘）

### 2.1 数据源可靠性战役（耗时最长，坑最多）

| # | 问题 | 根因（实测验证） | 解决方案 |
|---|---|---|---|
| 1 | 炸板数永远 0 | 东财 ZBPool/DT 接口只有 `sort=fbt:asc` 返回数据，其他 sort 返回空数组 | 全部改 `fbt:asc`（v9.26.18） |
| 2 | 资金走势图空白 | push2his 对机房 IP 持续 TLS ban + Promise.all 40并发触发限流 | 分批串行+重试+降级；最终**放弃 push2his**，改用行业快照直接画（v9.26.21→9.30） |
| 3 | 主力净流出永远 0 | 东财 clist `po=1` 降序只返回 f62 最大前 100（全正），流出被挤出；**pz 有上限 ~100** | `po=1` + `po=0` **双请求**合并（v9.30.2） |
| 4 | 人气榜"待接入" | v9.27 误判"emappdata 无 CORS 必须走 proxy"；实测 **完全支持 CORS**，且对 nodejs TLS ban | 浏览器直连 + 新增同花顺双榜交叉比对（v9.31） |
| 5 | cron 落库失败 | push2 对 nodejs 直连 TLS ban | 改用 **push2delay**（延迟15分钟行情，node 可直连）（v9.33） |
| 6 | 大宗交易 0 笔 | 报表名 `RPT_DATE_TRADE` 不存在；`PREMIUM_RATIO` 为小数需 ×100 | 正确报表名 `RPT_DATA_BLOCKTRADE`（v9.33） |

1. **模块化极好**：58 个 lib 模块每个职责单一（stageModel 管阶段、trapDetector 管诱多、positionSizing 管仓位），函数式纯函数为主，便于单测与复用

## 四、经验教训（最值钱的沉淀）

### 4.1 方法论级教训

1. **"接口不可用"必须实测三层**：curl 直连 → node 直连 → 浏览器直连，三层结果可能完全不同（emappdata 案例：curl✓/node✗/浏览器✓）
2. **不要硬撑不可靠的数据管道**：push2his 花了 3 个版本试图"修复"，最终放弃改用可靠数据源重写——**降级比修补更优**
3. **用户验收才是真测试**：v9.26.17 组件写完 tsc 通过但用户看不到——**"组件写好了" ≠ "功能生效"**，必须全链路（import→prop→渲染→视觉）验证
4. **双榜交叉验证是金融数据的标配**：单一数据源失真风险高（涨停榜糊弄人气榜的教训）
5. **数据管道不可靠时先降级到现有可靠数据**，再逐步补齐（资金走势图案例）

### 4.2 工程习惯教训

1. **修改后立即验证**：tsc + 接口实测 + 部署后 curl 验证 title/接口返回
2. **每次发布走固定流水线**：stamp → CHANGELOG → build → 复制 root → git → push → pm2
3. **坑要沉淀**：所有东财接口特性都写进了交接文档与记忆（push2delay 可直连、sort=fbt:asc、PREMIUM_RATIO×100 等）

## 六、幻方量化方法论解锁（High-Flyer 解密）

### 6.1 幻方核心方法论（公开信息调研）

幻方（High-Flyer）是国内头部 AI 量化私募（梁文锋创立，与 DeepSeek 同源算力），其方法论可归纳为**"三层策略金字塔"**：

```
┌─────────────────────────────────────────┐
│ 顶层 · 风险预算层                         │
│  CVaR 动态分配风险 · 单策略连续亏损熔断    │
│  （回撤>阈值自动降杠杆/切换防御模式）      │
├─────────────────────────────────────────┤
│ 中层 · 策略工厂层                         │
│  强化学习元策略生成器 · 按市场状态动态调整 │
│  （趋势市→提高持仓周期；震荡市→高频套利）  │
├─────────────────────────────────────────┤
│ 底层 · 因子库层                           │
│  200+ 因子（量价40%/基本面30%/另类20%）   │
│  遗传算法动态筛选 · AutoML 自动特征生成    │
│  情绪因子（NLP 舆情）· 资金流因子          │
│  每周迭代因子库 · 单模型数万维特征         │
└─────────────────────────────────────────┘
```

**可迁移的三条思想**（不抄 800 纳秒延迟和 1 万 GPU，抄方法论）：

| 幻方思想 | 游资版翻译 | 本项目可落地 |
|---|---|---|
| **因子库 + 动态筛选** | 你盘中的每个信号都是"因子"，关键是知道哪个因子现在有效 | 信号历史回测引擎（第 7 节 S1） |
| **市场状态自适应** | 同样一个信号，牛市里有效、熊市里是陷阱；要先判"今天是什么市" | 市场状态机（第 7 节 S2） |
| **风险预算 + 熔断** | 总仓位是"预算"，不是每笔单独决定；连亏 3 天必须降杠杆 | 组合风险预算升级纪律面板（第 7 节 S3） |
| **情绪因子（NLP）** | 舆情热度是另类数据 | ✅ 已有 LLM 新闻评分 |
| **逆向交易非理性波动** | 散户恐慌抛售=游资接筹点 | 溢价分布+核按钮已覆盖部分 |

### 6.2 幻方 vs 游资的本质差异（认知校准）

- 幻方赚的是**统计套利**的钱（每秒几百笔、赚 0.1-0.5 基点价差、年化靠复利）
- 游资赚的是**情绪周期**的钱（每天 1-3 笔、赚 10-20% 的板、靠确定性）
- **两者互补**：幻方的"因子验证/状态识别/风险预算"是游资该学的；游资的"主线/情绪/席位"是幻方量化不了的（NLP 情绪因子也只是近似）

- 每个状态给出**状态定义 + 当前证据 + 历史统计**（该状态出现的概率、之后 1-3 日表现）
- 状态影响：五问条操作建议 + positionSizing 闸门系数 + 仓位上限（如"分歧退潮"状态单票上限降到 15%）
- 价值：把"同样信号在不同市场下结果不同"这个游资直觉系统化

**S3. 信号历史回测引擎（幻方"因子验证"落地）**（工作量 L）
- 用 PG `zt_snapshot` 历史快照（已存多日）+ `kv_store` 历史资金/情绪 → 构建信号→结果的样本库
- 为 10 个核心信号打分：如"题材第N天+炸板率X%后3日主线胜率""核按钮后次日情绪分布"
- 前端"信号有效性"面板：每个信号显示历史样本数/胜率/平均收益
- 价值：解决"30 个信号不知道信哪个"，让决策有历史数据支撑

### A 级（下轮）

- **A1. 组合风险预算**：纪律面板升级——总仓位 = 基础仓位 × 市场状态系数 × 连亏熔断（连亏3天自动降半仓提示）
- **A2. 封单/炸板时序曲线**：单只股票的分时封单变化图（复用板块资金走势图技术）
- **A3. 竞价强度榜**：9:15-9:25 竞价金额/竞价涨幅排行榜（抢筹信号）
- **A4. 龙虎榜×涨停池交叉**：今日涨停股中哪些有龙虎榜席位加持（明日溢价增强信号）

### B 级（工程质量）

- **B1. vitest 单测**：stageModel/trapDetector/positionSizing/stockExit 4 个纯函数引擎
- **B2. App.tsx 拆分**：refreshAll → useOverview/useBattlePlan/useFund hooks
- **B3. any 类型清零**：涨停池/快照数据全字段类型化
- **B4. LimitBoard 收敛**：涨停池 fetch 统一到 api.ts（GLM5.2 卫生4）

## 八、最终结论

这个项目已经从"看盘工具"进化成"**带决策大脑的游资作战参谋**"：识别主线（LLM+规则双引擎）、判断阶段（权威词表）、识别诱多（陷阱引擎）、给仓位（定量化）、给离场（7条规则）、自动复盘（LLM）、推演次日（三剧本）、盯风险（系统+个股+黑天鹅）、接数据（东财/同花顺/腾讯多源交叉）。

**下一步最值得投入的方向**：不是再加新信号，而是把已有的 30+ 信号**做有效性验证**（S3）并**做市场状态自适应**（S2）——这正是幻方方法论的精髓：**少而准的信号 + 知道信号什么时候有效 + 严格的组合风险预算**。
