## 二、本地部署架构方案（推荐）

```
┌──────────────────────────────────────────────────────┐
│ 本机 Windows                                          │
│                                                      │
│  浏览器 localhost:8080                                │
│     │  http://localhost:8080/                        │
│     ▼                                                │
│  ┌──────────────────────────────────────────────┐    │
│  │  Node 本地服务（一个进程，PM2 守护）            │    │
│  │  · 静态托管：docs/index.html（v9.25 单文件）     │    │
│  │  · /api/proxy/*：东财数据转发（解决 CORS/限流）  │    │
│  │  · /api/db/*：前端数据读写 PostgreSQL          │    │
│  │  · 定时任务：交易日 15:30 收盘快照抓取写库       │    │
│  └──────────────┬───────────────────────────────┘   │
│                 │ node-postgres (pg)                 │
│                 ▼                                    │
│  ┌──────────────────────────────────────────────┐    │
│  │  PostgreSQL 16 (localhost:5432)              │    │
│  │  新建库 stock_monitor                         │    │
│  │  表：news / announcements / zt_snapshot /     │    │
│  │      seats / signals / watchlist / reviews /  │    │
│  │      playbooks / settings / sentiment_daily   │    │
│  └──────────────────────────────────────────────┘    │
└──────────────────────────────────────────────────────┘
```

### 设计要点

1. **一个 Node 进程搞定全部**：静态托管 + API 代理 + DB 读写 + 定时任务，避免 Nginx/多个服务复杂度
2. **前端改动最小**：现有 `dataStore.ts` 已预留"换成 fetch 零改动"的抽象层（源码注释明确写了），改读写实现即可；`localStorage` 降级为**离线缓存兜底**（断网仍可看旧数据）
3. **东财请求走代理**：浏览器直连东财有 JSONP/CORS 限制、易限流，本地代理统一转发 + 短 TTL 缓存（5-10 秒），顺带解决"人气榜 POST 接口"问题
4. **定时抓取摆脱"必须开网页"**：Node cron 交易日 15:30 后自动抓涨停池/龙虎榜/两融快照写 PG，跨日数据不再空洞
5. **API Key 放本机**：AI Key 不再暴露在 GitHub Pages 公网，本地更安全

## 三、实施步骤（分阶段，每阶段可独立验收）

### 阶段 1：本地先把 v9.25 跑起来（0.5 天，无代码改动）
1. 建 PG 库：`CREATE DATABASE stock_monitor;`（需 postgres 密码）
2. 新建 `server/` 目录：Express 静态托管 `docs/index.html`
3. 浏览器访问 `http://localhost:8080` 验证页面功能与 GitHub Pages 一致
4. 验收：本地页面可开、数据从东财正常加载

### 阶段 2：数据落库（1-2 天，核心改造）
1. PG 建表（SQL 脚本）：news / announcements / zt_snapshot / seats / signals / watchlist / reviews / playbooks / settings / sentiment_daily
2. `server/` 增加 `/api/db/*` 路由（get/put/delete）
3. 前端 `dataStore.ts` 及核心存储模块改造：优先 `/api/db` 读写，`localStorage` 做离线缓存
4. 首次启动做**存量迁移**：把 localStorage 现有数据一次性导入 PG
5. 验收：换浏览器打开本地页面，自选股/复盘/龙虎榜台账仍然在

### 阶段 3：API 代理 + 定时快照（1 天）
1. `server/` 增加 `/api/proxy/*` 转发东财（含 5-10s 缓存 + 限流）
2. 前端 `api.ts` 数据源切到代理（保留直连 fallback）
3. node-cron 定时任务：交易日 15:30 抓涨停池/龙虎榜/两融快照写库
4. 验收：收盘后不开页面，次日数据连续无空洞

### 阶段 4：运维与体验（0.5 天）
1. PM2 守护本地服务（开机自启，崩溃自动拉起）
2. 可选：局域网访问（手机看盘，需 Windows 防火墙放行 8080）
3. 备份策略：pg_dump 每日定时备份到本地目录

## 五、风险与注意事项

1. **东财接口稳定性**：本地代理能缓解限流，但东财接口本身随时可能调整（本项目已有 apiHealth 遥测可监控）
2. **PG 密码安全**：若改 trust 认证仅限本机 localhost，勿暴露局域网
3. **数据一致性**：localStorage 迁移到 PG 一次性完成，迁移脚本先备份
4. **磁盘占用**：PG 数据目录在 C 盘，快讯/公告 30 天滚动 + 快照，初期 <500MB，无需额外配置
5. **不增加依赖**：按项目规矩，服务端新增依赖（express、pg、node-cron、pm2）是合理的，因为这是新增后端层，不影响前端包体
